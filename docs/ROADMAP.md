# Engineering roadmap

## Completed Phase 0 foundation

- Preserved the original remote history and established frequent verified pushes
  on `phase0/foundation`; the local workspace initially had no checkout.
- Installed the mandatory access policy in project instructions, preserved the
  CSP/Content Manager locks, and used no GUI/DCC application automation.
- Audited exact reference versions, Pure source guards, saved graphics choices,
  installed interface candidates and historical ReShade evidence.
- Implemented read-only file preservation, native GPU probing, configuration
  schemas, evidence-gated planning, benchmark analysis/comparisons and original
  shader compilation feasibility with CPU-reference tests.
- Verified the tracked source independently of private `.local/` data and wrote
  architecture, limitations, reproduction and continuation documents.

Foundation delivery does not close the stable-build or visual/hardware gates.

## Next exact milestone: Phase 0B integration evidence

Produce a read-only runtime capability receipt for each permitted CSP track
and each Pure mode, using authorized isolated installations or supplied captures.
Do not apply the color prototype or change the owner's working installation.

Prerequisites:

1. An authorized isolated CSP 0.2.11 environment and its matching SDK/API inventory;
   no installation switching, copied live scenes or locked binary replacements.
2. A supported native CSP/game integration path that can read version, module,
   pipeline and buffer information without injecting an unrelated renderer or
   initializing Windows computer-use. If unavailable, record the gateway limit
   using the bounded policy and stop dependent runtime work.
3. A legally supplied Pure package/hotfix inventory and permission to use it in
   the isolated environment; keep proprietary assets and raw configuration private.
4. A reproducible native-resolution scene/capture record and an explicit identity
   of the game's GPU, driver, output encoding, display mode and timing source.

Acceptance:

- Exact version and capability evidence for 0.2.11 and preview361 without upgrades.
- Documented Gamma/LCS exposure and post-processing ownership, real texture
  format/encoding, callable interfaces and graceful unsupported-feature handling.
- Validated timing units and pause/replay semantics; independently scoped game
  memory evidence if a supported interface exists, otherwise unknown.
- FSR integration prerequisites, loaded payload/versions and buffer/reset evidence
  before any temporal eligibility; frame generation stays a separate gate.
- Native baseline captures, unchanged audited input hashes and a committed,
  pushed, remotely verified receipt/handoff. No visual-performance claim yet.

## Later milestones and gates

| Milestone | Deliverable | Required gate |
|---|---|---|
| 1: Visual foundation | Thin supported CSP/Pure adapter, identity processing, separate Gamma/LCS calibrations | Isolated runtime evidence, texture/encoding validation, GPU readback versus CPU reference and user visual review |
| 2: Legacy hardware characterization | Physical 2/3-4/6/8 GB AMD/NVIDIA benchmarks and capacity policy revisions | Matched native/effect captures, repeatability, game memory, frame-time consistency, driver evidence |
| 3: Original effect module | Optional fused color processing only where it adds value | Visual approval and measured GPU/frame-time/resource cost with disable/rollback tests |
| 4: Supported reconstruction/adaptation | Existing CSP FSR choices, optional bounded quality recommendations | Per-track capability evidence, temporal artifact review and stable control hysteresis; native retained |
| 5: Cinematic integration | Versioned profile/capture contract consumed by the separate replay/camera MCP | Existing approved game-native interfaces; no replay MCP is developed as part of Phase 0 |
| 6: Distribution | Reviewed installer/package, license and public hardware matrix | Ownership-aware install/rollback, extracted-package validation and release authorization |

Do not turn unsupported measurements into defaults or promise FPS from nominal
memory tiers. GPU marketing names are examples, not eligibility lists. Do not
require FSR4, DLSS, RTX/Tensor hardware, ray tracing or a new driver. Licensing,
HDR/VR calibration, third-party compatibility and representative low-memory
hardware remain explicit release work.
